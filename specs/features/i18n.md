# Feature: Інтернаціоналізація (UK / EN)

**Status:** Ready for implementation  
**Priority:** 8  
**Agent:** requirements-planner → backend + database + frontend → tester → plan-verifier → code-reviewer → security-reviewer

---

## Summary

Двомовний (українська / англійська) shop: UI-рядки через `@jsverse/transloco`, локалізований контент товарів і категорій у БД, префікс локалі в URL публічного storefront, language switcher з persist, і admin-вкладки UK/EN для ручного введення перекладів. Фіча **ретрофітить** уже реалізований українськомовний код (каталог, товар, кошик, checkout, auth, home, admin), а не лише greenfield.

## Scope

Full-stack: ASP.NET Core API + Angular UI + PostgreSQL migration.

### In scope

- Extract усіх hardcoded UI-рядків storefront і admin у `ua.json`; committed `en.json` (ручний переклад UI-рядків).
- Language switcher у header (storefront, auth, admin); persist: URL (storefront) + `localStorage`; українська — default і fallback.
- Префікс локалі на всіх **публічних** маршрутах: `/ua/...`, `/en/...` (home, catalog, product, cart, checkout, order confirmation, auth, profile).
- `/admin/*` **без** префікса локалі; мова UI лише з switcher + `localStorage`.
- Legacy URL без префікса → redirect на `/ua/...` (той самий path + query); bare `/` → завжди `/ua/`.
- БД: rename product/category text columns → `*_uk`, add nullable `*_en`; fallback на UK коли EN порожній.
- Публічні DTO без зміни форми (`name`, `shortDescription`, `description`, category `name`); service обирає колонку за locale.
- Admin payload: bilingual fields (`nameUk` / `nameEn`, …) на існуючих `/api/products`, `/api/categories`.
- Locale resolution на всіх **read** endpoints, що повертають відображувані назви product/category.
- Admin UK/EN tabs для ручного заповнення EN (без автоперекладу).
- hreflang + canonical на home, catalog, product.
- Pluralization і форматування дат/чисел за активною локаллю.
- Ціни лишаються в UAH для обох локалей (без конвертації валют).
- Catalog card «від» / «from» price copy (product-variants): UK `від {{price}} ₴`, EN `from {{price}} ₴` via Transloco; weight units (`г`/`кг`/`шт`) stay API data strings (no Transloco for units in v1).
- ProductVariant has **no** translated fields.

### Out of scope

- Третя мова.
- Будь-який machine-translation provider (DeepL, Google Translate, тощо) і endpoint автоперекладу.
- Переклад email / order notification templates (окрема фіча); reset-password links у листах лишаються без locale prefix.
- Локалізація API `error` / FluentValidation messages (лишаються українською).
- Окремі SEO title/description fields і image alt columns (alt як зараз — від назви товару).
- SSR / prerender обох локалей (follow-up; ця фіча — client Angular i18n).
- Nginx/Docker redirect rules (лише Angular route redirects; deploy може додати пізніше).
- CI-автоматизація sync `ua.json` → `en.json` (v1: ручний переклад + commit).
- Зміна Nova Poshta API; лише UI-copy через Transloco.
- Currency conversion.

## 1. Data & API

### 1.1 Locales

| Code | Role |
|------|------|
| `ua` | Default, fallback, `x-default` hreflang target |
| `en` | Second locale |

Resolution order for API reads that return display names:

1. Query `?locale=ua|en` (case-insensitive; invalid → ignore and continue)
2. `Accept-Language` header (prefer `uk*`/`ua*` / `en*` → app locale `ua`/`en`; first usable match)
3. Fallback `ua`

Writes (POST/PUT/DELETE) не змінюють контракт через locale; admin bilingual fields передаються явно.

### 1.2 Database migration (retrofit)

**Products** (`products` table):

| Before | After | Nullability |
|--------|-------|-------------|
| `name` | `name_uk` | NOT NULL (existing values preserved via rename) |
| — | `name_en` | nullable |
| `short_description` | `short_description_uk` | nullable as today → keep nullable unless already NOT NULL |
| — | `short_description_en` | nullable |
| `description` | `description_uk` | nullable as today |
| — | `description_en` | nullable |
| `slug` | `slug` | unchanged — **single shared UNIQUE slug** for both locales |

**Categories** (`categories` table):

| Before | After | Nullability |
|--------|-------|-------------|
| `name` | `name_uk` | NOT NULL (rename in place) |
| — | `name_en` | nullable |
| `description` | `description_uk` | nullable as today |
| — | `description_en` | nullable |
| `slug` | `slug` | unchanged — shared UNIQUE |

Rules:

- Prefer **rename** columns to `*_uk` (not copy-then-drop of parallel old names), then add `*_en`.
- Existing live DB rows must survive; seeded demo may already be gone — still preserve whatever products/categories exist.
- Empty / null English → public API returns Ukrainian value for that field.
- Ukrainian text fields that were required stay required (`name_uk`); English never required on save.

**OrderItem:** model has `ProductId`, `Quantity`, `UnitPrice` — **no name snapshot**. Display names on order read are resolved from the live `Product` (and category if shown) using request locale + UK fallback. **Limitation (documented):** later edits to product EN/UK names can change how historical orders appear; acceptable for v1.

**Cart lines:** `GET /api/cart` resolves live product/category display names via locale (same fallback).

### 1.3 Content selection (service layer)

For each translatable field on public reads:

- If locale is `en` and `*_en` is non-empty → use EN
- Else → use `*_uk`

Public DTO shape **unchanged**: single `name`, `shortDescription`, `description`, category `name` / nested category name fields as today.

### 1.4 Search

`search` on `GET /api/products` matches **both** UK and EN text columns (OR across name / short / description as currently searched). Result rows still expose names in the **active** locale (selection rule above).

### 1.5 Endpoints — locale-aware reads

Locale resolution applies to every read that returns product or category **display names**, including:

| Method | Route | Notes |
|--------|-------|-------|
| GET | `/api/products` | List / filters / home featured if same endpoint |
| GET | `/api/products/:slug` | Detail + similar products’ names |
| GET | `/api/categories` | Tree names / descriptions |
| GET | `/api/cart` | Line `name`, category name |
| GET | `/api/orders/:id` | Line product names from Product |
| GET | `/api/admin/orders`, `/api/admin/orders/:id` | Line / product names localized for admin’s requested locale |
| GET | `/api/orders` (profile list) | If line/product names exposed — localize |

Frontend sends `?locale=` matching the active UI locale on these calls (in addition to any Accept-Language the browser sends).

API `error` strings and FluentValidation messages: **unchanged Ukrainian** (out of scope).

### 1.6 Admin product / category payloads (contract change)

Same routes as today (`POST/PUT /api/products`, `POST/PUT /api/categories`, admin GETs that return editable product/category). Public list/detail for anonymous shoppers keep monolingual fields. When the caller is Admin loading the form / saving:

**Product (admin):**

- `nameUk` (required), `nameEn` (optional)
- `shortDescriptionUk`, `shortDescriptionEn` (optional)
- `descriptionUk`, `descriptionEn` (optional)
- `slug` — single; **auto-generated from `nameUk` only** (editable rules as in admin.md); preview path uses shared slug
- Other fields unchanged (price, images, flags, `categoryId`, …)

**Category (admin):**

- `nameUk` (required), `nameEn` (optional)
- `descriptionUk`, `descriptionEn` (optional)
- `slug` — single shared; auto from `nameUk`
- Hierarchy fields unchanged (`parentId`, …)

Saving with empty English fields is allowed (runtime fallback to UK on public reads).

Admin product list search continues to search name/slug; after migration, search should hit UK+EN name columns as well as slug (consistent with public search intent).

### 1.7 Caching

- Category tree may still be reused between visits **per locale** (do not serve EN names from a UK-cached tree).
- Product list/detail and cart: refresh on navigation / filter change / locale switch as today (locale change forces refetch of locale-sensitive data).

## 2. Routing, SEO, and language preference

### 2.1 Storefront URL pattern

All public storefront routes gain a locale prefix:

| Legacy (still accepted) | Canonical |
|-------------------------|-----------|
| `/` | `/ua/` or `/en/` (see bare `/`) |
| `/catalog` | `/ua/catalog`, `/en/catalog` |
| `/catalog/:slug` | `/ua/catalog/:slug`, `/en/catalog/:slug` |
| `/cart` | `/ua/cart`, `/en/cart` |
| `/checkout` | `/ua/checkout`, `/en/checkout` |
| `/order/:id` | `/ua/order/:id`, `/en/order/:id` |
| `/profile` | `/ua/profile`, `/en/profile` |
| `/auth/login` (and other auth pages) | `/ua/auth/...`, `/en/auth/...` |

Shared product/category **slug** is identical in both locales (e.g. `/en/catalog/chay-romashka` uses the same slug as UK).

Catalog query params (`category`, `sortBy`, `page`, price filters, etc.) are preserved on legacy redirect and on UK↔EN switch.

### 2.2 Admin routes

- `/admin/*` remains **without** locale prefix (e.g. `/admin/products`).
- `adminGuard` and shell behavior unchanged aside from Transloco + switcher.

### 2.3 Legacy redirects

- Any storefront URL **without** locale prefix → redirect (302 or Angular equivalent) to **`/ua` + same path + query**.
- Bare `/` always redirects to `/ua/` (Ukrainian default). Language switcher still allows EN.
- Exception for Accept-Language on bare `/` was removed in favor of a fixed UK default.
- Email reset links may still point at `/auth/reset-password?token=…` (out of scope to change emails) → legacy rule sends them to `/ua/auth/reset-password?token=…`.

### 2.4 Default locale

Ukrainian (`ua`) is the default for bare `/`, Transloco `defaultLang` / `fallbackLang`, and missing storage. English is opt-in via the language switcher or `/en/...` URLs.

### 2.5 localStorage vs URL

- Storefront: **URL locale wins**; on resolve, update `localStorage` to match.
- Admin (no URL locale): switcher updates Transloco active lang + `localStorage` only; does **not** navigate to `/en/catalog` while staying in admin.
- When user follows a storefront link from admin (logo, «магазин», etc.), navigate using the **stored** locale prefix.

### 2.6 Language switcher

- Visible in header on storefront, auth, and admin.
- Storefront: client-side navigate — replace locale segment, keep the rest of the path and query; full reload not required; refetch locale-sensitive API data.
- Admin: change UI language only (Transloco + storage).
- Ukrainian remains fallback for missing Transloco keys.

### 2.7 SEO

On **home**, **catalog**, and **product** pages:

- `hreflang` alternates use BCP 47 `uk` / `en` (pointing at `/ua/...` and `/en/...` URLs), plus `x-default` → `/ua/...`
- `x-default` points at the **Ukrainian** equivalent URL
- `canonical` = current localized URL

SSR/prerender for both locales: **out of scope** (note as follow-up). This feature ships client-side i18n + meta tags as supported by the current Angular setup.

Redirect implementation for this feature: **Angular routes only** (deploy/nginx rules optional later).

## 3. UI — Transloco retrofit

### 3.1 Library and files

- Use `@jsverse/transloco` with standalone Angular components (signals-compatible usage as supported by the library).
- `ua.json` — source of truth for extracted Ukrainian UI strings (every hardcoded template/code string from storefront + admin).
- `en.json` — committed translation file; filled and updated **manually** (no machine-translation tooling in this feature).
- Process for new strings: add to `ua.json` → add English equivalent in `en.json` → commit both.

### 3.2 Surfaces (full bilingual UI)

All user-visible chrome, including:

- Home / featured
- Catalog (filters, sort, empty, errors, a11y labels, plurals «N товари» / EN equivalents)
- Product page
- Cart drawer + `/cart`
- Checkout + order confirmation
- Auth (login, register, forgot/reset) + profile
- **Entire admin** (sidebar, tables, forms, toasts, IsActive/IsAvailable labels, confirm dialogs, empty/error)

Client-side validation messages shown in UI: Transloco. Server `error` text may still be Ukrainian when surfaced in toasts (acceptable per out-of-scope API messages).

### 3.3 Pluralization and formatting

- Plural rules for UK and EN for count labels (cart badge text, catalog «N products», etc.).
- Dates and numbers follow the active locale (`ua` / `en`).
- Currency display remains UAH (₴) for both locales; no conversion.

### 3.4 Admin translatable fields UI

- Each translatable field group renders as a **UK / EN tab pair** (or equivalent tabbed field group).
- **Product field groups:**
  1. Name
  2. Short description
  3. Description
- **Category field groups:**
  1. Name
  2. Description (when the description field is shown)
- English values are entered **manually** on the EN tab. No auto-translate button or translation API.
- Empty EN on save allowed (public reads fall back to UK).
- Slug UI: still one slug; generated from UK name; category filter preview uses shared slug (`/catalog?category=…` in admin preview may show without locale or with stored locale — public links use `/ua|en/catalog?category=`).

### 3.5 Nova Poshta / checkout copy

- Delivery labels and helper text via Transloco only.
- NP city/branch API unchanged; phone still `+380…`.

## 6. Edge cases and retrofit impact

- **Missing EN content:** always show UK text for that field; do not show blank names.
- **Missing Transloco key:** fall back to Ukrainian catalog / key strategy configured for Transloco (UK fallback).
- **Shared slug:** EN pages never use a different slug; no `slug_en`.
- **Legacy bookmarks:** `/catalog/foo?sortBy=new` → `/ua/catalog/foo?sortBy=new`.
- **URL vs storage mismatch:** URL wins on storefront; storage updated.
- **Order history names:** resolved from current Product; EN/UK edits can alter historical display (no OrderItem name column).
- **Search:** query can match EN text while UI is UK (or vice versa); returned `name` still follows active locale.
- **Prices:** UAH both locales; sort/filter by price unchanged.
- **Permissions:** bilingual admin writes — Admin only.
- **Long text:** existing truncate rules apply to whichever locale string is shown.
- **Retrofit conflict with older feature specs:** older specs say Ukrainian-only copy and unprefixed routes (`/catalog`, `/cart`, …). **This feature supersedes those URL and copy rules**; implementers update related docs during the build (see References).

## Acceptance Criteria

### Routing & preference

- [ ] All public storefront routes are available under `/ua/...` and `/en/...` (home, catalog, product, cart, checkout, order confirm, auth, profile).
- [ ] `/admin/*` has no locale prefix; switcher changes UI language + `localStorage` without forcing storefront navigation.
- [ ] Legacy unprefixed storefront URLs redirect to `/ua` + same path and query.
- [ ] Bare `/` always redirects to `/ua/` (Ukrainian default; not Accept-Language).
- [ ] UK↔EN switch preserves path after locale segment and catalog query params; URL updates `localStorage`.
- [ ] Language switcher appears on storefront, auth, and admin headers.

### Content & DB

- [ ] Product columns renamed to `name_uk` / `short_description_uk` / `description_uk` with nullable `*_en`; existing row data preserved as UK.
- [ ] Category `name_uk` / `description_uk` + nullable `*_en`; shared unique `slug` unchanged for products and categories.
- [ ] Public API returns single-name fields chosen by locale with UK fallback when EN empty.
- [ ] Admin create/update accepts and returns bilingual fields; empty EN allowed; slug auto from `nameUk` only.
- [ ] Search matches UK and EN text; response names follow active locale.
- [ ] Cart GET localizes line names; order line names resolve from Product at read (limitation documented).

### API locale

- [ ] Locale resolution `?locale=` → Accept-Language → `ua` on all reads that expose product/category display names (including cart and orders).
- [ ] No translation/proxy endpoint; no DeepL (or other MT) config or client exposure.

### UI (Transloco)

- [ ] Hardcoded Ukrainian UI strings extracted to `ua.json`; `en.json` committed with manual translations; `@jsverse/transloco` used across storefront and full admin.
- [ ] Proper pluralization and locale-aware date/number formatting for `ua` and `en`.
- [ ] Admin translatable fields use UK/EN tabs for manual entry (product: name, short, description; category: name, description); empty EN allowed.
- [ ] Prices remain UAH for both locales; NP API unchanged; client validation copy via Transloco.

### SEO

- [ ] Home, catalog, and product pages expose `hreflang` for BCP 47 `uk`/`en` and `x-default` (→ `/ua/...` URL); canonical is the current localized URL (`/ua` or `/en`).

### Out of scope confirmed

- [ ] No third language; no machine translation; no email template translation; no API validation-message i18n; no SSR dual-locale in this feature; no currency conversion.
